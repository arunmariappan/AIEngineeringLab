There's no setting on this model that makes it stop. So from Week 2, we stop eyeballing and start measuring.
  1. 1

    Open the repo and a terminal

    In VS Code, open the week1-llm-foundations folder, then Terminal › New Terminal.

    ExpectedThe terminal prompt ends in week1-llm-foundations.
  2. 2

    Run the same prompt three times

    Part 1 of the script asks for a one-sentence tagline for a cold-brew coffee shop, three times, with exactly the same prompt.

    Terminal
    uv run lab1_first_call.py

    Before you scroll on: how many different answers did you get? Compare with your neighbour.

    ExpectedThree different taglines. If two match, run it again; they rarely stay the same.
  3. 3

    Turn the knob you do have: effort

    Part 2 asks one question at three effort levels: low, medium, high. Effort sets how hard the model thinks, not how random it is. Write down what you see:

    effortoutput tokenssecondsanswer changed?
    low
    medium
    high
    Check the arithmetic (try it yourself first)

    09:40 → 13:15 is 3 h 35 min. Minus the 25-minute stop, the train was moving for 3 h 10 min.

    ExpectedThree --- effort=… lines. Output tokens usually rise with effort, because thinking tokens are billed as output. The seconds go up with them.
  4. 4

    Read how the answer is picked out

    Open lab1_first_call.py and find these two pieces. A response is a list of blocks, not a string. This model thinks by default, so the first block can be a thinking block:

    lab1_first_call.py
    def text_of(message) -> str:
    """A response is a LIST of content blocks, not a string.

    Haiku 5.5 thinks by default, so the first block can be a `thinking`
    block. Pick the text blocks by their type, never by position.
    """
    return "".join(block.text for block in message.content if block.type == "text")

    And max_tokens is one ceiling for thinking and answer together:

    lab1_first_call.py
    message = client.messages.create(
    model=MODEL,
    max_tokens=1024,                     # a CEILING for thinking + answer together, not a target
    output_config={"effort": effort},    # low | medium | high | xhigh | max
    messages=[{"role": "user", "content": prompt}],
)
    ExpectedYou can say why message.content[0].text would break on this model.
  5. 5

    Try to pin it down

    STRETCH

    Older models had a temperature dial. Add temperature=0, as a new line inside the client.messages.create( call, save, and run again:

    Terminal
    uv run lab1_first_call.py

    Read the error, then take the line out again.

    ExpectedTypeError: Messages.create() got an unexpected keyword argument 'temperature', raised before anything is sent. On this model you can't opt out of variance.
  6. 6

    Starve it of tokens

    STRETCH

    Change max_tokens=1024 to max_tokens=200, and add message.stop_reason to the Part 2 print line. Run the lab again and look at the effort=high answer. Put 1024 back afterwards.

    ExpectedAt higher effort the answer may come back short or empty, with stop_reason = max_tokens: the thinking used up the budget.

If something goes wrong

AuthenticationError … 401 … invalid x-api-key

Your .env still has the placeholder, or the key has quotes or spaces around it. Fix it, save, and run again.

ModuleNotFoundError: No module named 'anthropic'

You ran python outside the project's environment. Use uv run lab1_first_call.py, which uses the right environment every time.

RateLimitError (429) or overloaded (529)

Ten people are calling at once. Wait 20 seconds and run it again. Nothing is wrong with your code.

A run prints nothing where the answer should be

The answer ran out of room after thinking. Check that max_tokens is still 1024.

“uv” is not recognized

Go back to the setup page, step 4, then close and reopen VS Code.
