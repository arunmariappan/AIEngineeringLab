  4. 4

    Read Python: the eight things

    Open bridge0_python.py in VS Code. Saturday's slide “Read Python in ten minutes” shows these eight things, and every one of them is in the file, marked with its number:

    #Looks likeSay it asIn bash
    1 · Importimport jsonBring in a toolbox someone else wrote.source a script
    2 · VariableMODEL = "pretend-model"A labelled box that holds a value.MODEL="x"
    3 · Functiondef fake_reply(prompt, effort="low"):A named recipe. effort has a default.a bash function
    4 · Calling itfake_reply(prompt, effort="high")Use the recipe, changing one setting by name.running a command with a flag
    5 · Loopfor run in range(1, 4):Do the indented lines below 3 times: 1, 2, 3.for i in 1 2 3; do
    6 · List, dict["low", "high"] {"low": 5}A list keeps order; a dict maps label → value.arrays
    7 · f-stringprint(f"run {run}: {answer}")Text with the blanks filled in.echo "run $i"
    8 · Comment# a note for humansPython skips everything after #.#, the same

    Indents matter. The indented lines under a line that ends in a colon belong to it: the body of the function, or of the loop. And Python counts the way range(1, 4) does: it stops before the end, so you get 1, 2, 3. Now read the main part of the file:

    bridge0_python.py
    if __name__ == "__main__":
    # CHANGE ME (Bridge 0, step 4): write your own prompt here, then run the file again.
    prompt = "Give me a one-sentence tagline for a coffee shop that only sells cold brew."

    # 5 · LOOP: do the indented lines 3 times. range(1, 4) gives 1, 2, 3 (it stops BEFORE 4).
    for run in range(1, 4):
        reply = fake_reply(prompt)                    # 4 · CALLING IT: use the recipe
        print(f"run {run}: {text_of(reply)}")         # 7 · F-STRING: text with the blanks filled in

    # 4 · CALLING IT again, changing one setting by name.
    reply = fake_reply(prompt, effort="high")
    print(f"\neffort=high: {reply['usage']['output_tokens']} output tokens")

    # The whole reply, printed as JSON: the shape every AI API sends back.
    print("\nThe full reply, as JSON:")
    print(json.dumps(reply, indent=2))

    New to all of this? Python from zero takes each of the eight one lesson at a time, with a file to run and change.

    ExpectedYou can read each line of that block aloud as a sentence: “for each run from 1 to 3, get a fake reply and print its text”.

  6. 6

    Read the reply as JSON

    Every AI service answers in JSON: text that holds labels and values. Curly braces { } hold labels and values (a dict). Square brackets [ ] hold a list, in order. Look at the JSON your run printed and find three things:

    1. the answer: content → the block whose type is text → text
    2. the bill: usage → output_tokens
    3. the block before the answer: thinking. Real models think first, too.

    This is why every lab picks the text by its type, never by position: the first block may be thinking.

    ExpectedYou can point at the answer and the bill in the JSON, and say why content[0] isn't the answer.
  7. 7

    Break it on purpose, and read the error

    Change effort="high" to effort="hihg" and run the script. Python stops with a traceback:

    What you'll see (your folder path and line numbers may differ)
    Traceback (most recent call last):
  File ".../week1-llm-foundations/bridge0_python.py", line 58, in <module>
    reply = fake_reply(prompt, effort="hihg")
  File ".../week1-llm-foundations/bridge0_python.py", line 38, in fake_reply
    "output_tokens": thinking_tokens[effort] + len(answer) // 4,   # thinking counts as output
                     ~~~~~~~~~~~~~~~^^^^^^^^
KeyError: 'hihg'

    Read it from the bottom up. The last line says what went wrong: a KeyError, meaning the dict has no label called 'hihg'. The lines above say where: the file, the line number, and the line itself. The top File line is where your code started; the bottom one is where it broke.

    Put high back. Now delete the closing ) at the end of the print(f"run … line and run again:

    What you'll see
      File ".../week1-llm-foundations/bridge0_python.py", line 55
    print(f"run {run}: {text_of(reply)}"
         ^
SyntaxError: '(' was never closed

    A SyntaxError means Python couldn't even read the file, so nothing ran. Put the bracket back.

    Last line saysUsually meansFix
    No such file or directoryYou're in the wrong folder.pwd, then cd into the week folder.
    ModuleNotFoundErrorYou ran python instead of uv run.Use uv run file.py.
    NameErrorA name is misspelt, or used before it's set.Check the spelling on that line.
    IndentationErrorThe indents don't line up.Line it up with its neighbours.
    KeyErrorA dict doesn't have that label.Check the label's spelling.
    AuthenticationError … 401The API key is missing or wrong.Expected until Saturday; then fix .env.
    ExpectedYou broke it twice, read both errors from the bottom up, and put it back. The script runs again.
  8. 8

    Git: save points for your work

    Git keeps a history of a folder. A commit is a save point with a message. Four commands cover Saturday: git status (what changed?), git diff (exactly what?), git add (include this in the next save point) and git commit (save it).

    You changed the script in step 5. Look, then undo it:

    Terminal
    git status
git diff
git restore bridge0_python.py

    git diff shows removed lines in red and added lines in green. If it fills the screen, press q to leave. Now make a first commit of your own. In VS Code choose File › New File, type one line, such as What I want from this course: …, and save it as my-notes.md in the week folder. Then:

    Terminal
    git add my-notes.md
git commit -m "My first commit"
git log --oneline -3

    Your commit stays on your laptop for now. Pushing sends commits to GitHub. You do that when you hand in, on your own private repo: the hand-in page shows how.

    Expectedgit status is clean after the restore, and git log shows “My first commit” at the top.
  9. 9

    What .env is, and why git never sees it

    .env is a small settings file of NAME=value lines. Your copy holds your class key. The labs read it with two lines at the top:

    lab1_first_call.py
    load_dotenv()          # reads ANTHROPIC_API_KEY (+ optional ANTHROPIC_BASE_URL) from .env
client = Anthropic()   # picks the key up from the environment

    The repo's .gitignore tells git never to track it. Check that for yourself:

    Terminal
    git check-ignore -v .env

    Your key is a password and a bill. It goes in .env and nowhere else: never in code, a chat, a screenshot or a commit. You'll get it on a printed slip at 09:30 on Saturday.

    Expected.gitignore:2:.env followed by .env: git will never commit that file.

Quick check

Answer in your head or on paper first, then open the answer. Not graded. If one surprises you, ask in the cohort WhatsApp group.

  1. You type uv run lab1_first_call.py and get “No such file or directory”. What do you check first?

    Answer

    Which folder you're in. Run pwd, then cd into week1-llm-foundations.

  2. What does range(1, 4) give you?

    Answer

    1, 2 and 3. It stops before the end.

  3. An error ends with KeyError: 'hihg'. What does it mean, and where's the line to fix?

    Answer

    The dict has no label 'hihg'. The File … line … lines just above it tell you where.

  4. Why does every lab pick the answer by block type, not content[0]?

    Answer

    The first block may be the model's thinking. Picking by type always finds the text.

  5. Where does your class key go, and where must it never go?

    Answer

    In .env only. Never in code, a chat, a screenshot or git.

If something goes wrong

git pull says your local changes would be overwritten

You changed a course file. Put your change aside, pull, then bring it back:

Terminal
git stash
git pull
git stash pop
“fatal: not a git repository”

You're outside the repo. Run cd AIEngineeringLab/week1-llm-foundations from the folder you cloned into.

“Author identity unknown” when you commit

Git doesn't know who you are yet. Do setup step 2, then commit again.

git diff or git log fills the screen and won't go away

It's showing one page at a time. Press q to leave.

“uv” is not recognized

Go back to setup step 4, then close and reopen VS Code.
