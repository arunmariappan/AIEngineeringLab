If something goes wrong

“remote upstream already exists” or “remote origin already exists”

You ran step 4 before. Check with git remote -v. If origin points at the wrong address, fix it:

Terminal
git remote set-url origin https://github.com/YOUR-USERNAME/ai-engineering-yourname.git
! [rejected] … (fetch first) when you push

Your GitHub repo isn't empty: it was created with a README. The easiest fix is to delete that repo (Settings › at the bottom, Delete this repository) and create it again, empty, then push.

“Support for password authentication was removed”, or it asks for a password

Sign in through the browser window instead. On Windows, if no window opens, update Git for Windows (setup step 2) and push again. On macOS, Git asks for a password in the terminal: paste a GitHub personal access token there, not your password. GitHub explains how.

“tag 'wk1-checkpoint' already exists”

You're handing in again after a fix. Move the tag to your latest commit and push it again:

Terminal
git tag -f wk1-checkpoint
git push -f origin wk1-checkpoint
“src refspec main does not match any”

Nothing is committed yet. Do step 2, then push again.

.env shows up in git status

Stop: don't add it. Check that .gitignore is in your week folder, and ask in the group before you push anything.
